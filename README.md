# 皇后 Queens

打开即玩的皇后推理小游戏：每行、每列、每个色块各放一只皇后，皇后之间不能相邻。
支持 4×4–16×16，每盘唯一解，带难度评估、逐步提示、撤销、分享码与续玩。
棋盘上方是一条**局内信息条**（棋盘 / 用时 / 步数 / 皇后 / 难度），点哪儿都进同一个「本局信息」页。
剩最后几只皇后时，提示行会换成一个「补齐」按钮，点一下挨个落子、一段快动画收尾。
设置里还有「挑战」（限时、禁用提示、禁用撤销）与「淡化」（填过的格子整格透成背景色，手停半秒才淡）。
设置面板默认只摊开「换一局」和它上面那几组，开关与分享折在「显示更多选项」里。
顶栏的奖杯记战绩：每局留一张棋盘缩略图、分享码，排行榜按**限时 × 难度**分开排，
全存在本机 localStorage 里。
顶栏的调色盘是**外观**：色块可以换成几何 / 自然 / 天空 / 贴纸四套纹样，叉可以换成点，
皇后可以换成小猫——满盘 × 看得眼花时换一套就安静了。三排样式由 `src/js/looks/` 里的插件提供。

## 局内信息

棋盘上方那一块（提示文案下面、棋盘上面）是这一局的读数，几段连成一条：

| 段 | 显示 | 说明 |
| --- | --- | --- |
| 棋盘 | `8×8` | 这一局的边长 |
| 用时 | `00:00` | 开了限时变成倒计时；最后 30 秒这一段转红慢闪 |
| 步数 | `↺ 12 步` | **撤销栈里还剩几步**。一步都没有时整段淡下去，栈满了写 `60+` |
| 皇后 | `1/8` | 放满时这一段变绿 |
| 难度 | `中等 5.2` | 圆点按分级上色；本局难度还没算出来时整段收起 |

- **步数是「还能退几步」，不是「走了几步」。** 假设推演到一半最容易忘的就是这件事：
  推了十几格，想退回分叉点却不记得要按几下撤销。这里读的就是撤销栈的深度，
  数字是多少就按几下——答的就是这个问题，别的都不必数。
- 拖动连涂一整行只算 **一步**（一整笔只压一个撤销点），双击标 × + 放皇后也算一步
  （第二下是同一个动作的收尾）。所以它不是格数，就是「按几次撤销」。
- 撤销栈的深度上限 `UNDO_MAX`（`core/state.js`，现在是 60）。到顶以后最早的几步真的
  撤不回去，所以读数写成 `60+` 而不是继续往上加——数字得跟能做的事一致。
  上限只有一处定义：`history.js` 的入栈也读它。
- 刷新页面后撤销栈是空的（存档里只存局面，不存历史），读数回到 0 —— 那时确实撤不动，
  不是数字坏了。
- **整条是一个按钮**，点哪一段都打开同一个「本局信息」页。以前是三个胶囊
  （只有尺寸那个能点、还开到设置面板里）加提示行右侧一个难度标签：
  四种样子、三种去向，全靠记忆分辨，所以并成一条、一个入口。
- 信息页里的卡片跟信息条一一对应（棋盘 / 用时 / 皇后 / 难度），步数那张另外占满一整行——
  它答的是「能退回几步」，跟前四项「这一局是什么样」不是同一类。
  下面是难度构成：五类推理各用了多少次、分数怎么来的。用时那张跟着心跳走，面板开着也在动。
- **难度构成只报事实，不下结论。** 那一行不写「不猜不试，纯推理就能推完」这种话——
  它跟玩家实际的推演顺序经常对不上。现在只写 `8×8 · 试推 7 次 · 纯逻辑可定 1/8 只`。
- **术语解释收在每行右端的问号里**（点开 / 悬浮 / 键盘 focus 才展开，点别处收起）。
  以前是面板底部五行常显小字，把读数挤得没地方。文案唯一出处是 `ui/difficulty.js` 的 `DIFF_ROWS`。
- **底部常显的是「读数与实际的差异」**，不是名词表：记账走的是程序的一条参考路径（不是唯一解法，
  换个起手同一只皇后可能记在别的技巧下）、`试错落子` 通常为 0（试推在 1200 次内基本都能推完）、
  分数只看边长 / 试推次数 / 开局推进率。
- 「试推次数」取 `steps.probe`（`explain()` 沿一条路径的记账），与 `假设试推 ×N` 同一个数；
  分数用的是 `analyze()` 另一次统计（上限 600 次），所以面板不给两者画等号。
- 页脚的「改棋盘大小与难度」是信息页里唯一的一个动作，点到设置面板；
  信息条本身只负责「读」，不改任何东西。
- 提示文案与信息条装在一个 `.stage-head` 里，两者一起贴在棋盘上方，
  在舞台上算**一块**：`ui/layout.js` 扣的是这一块的高度，开关浮层不会挪动棋盘。
- 落地：`#btnHud`（整条）→ `ui/difficulty.js` 的 `openDiff()`；
  各段是 `#hudSize` / `#timePill` / `#stepPill` / `#queenPill` / `#diffSeg`，
  读数由 `ui/render.js`（棋盘 / 步数 / 皇后）、`core/clock.js`（用时）与
  `ui/difficulty.js`（难度）写，样式在 `03-topbar.css`。


## 快速开始

```bash
# 方式一：双击（Windows）
启动局域网游戏.bat

# 方式二：任意系统
python serve.py          # 默认 8080，被占用会自动往后找
npm start                # 同上，只是包了一层
```

> **不要直接双击 index.html。** 应用已拆成 ES 模块，`file://` 协议下浏览器会拦掉模块加载。
> 编辑器里用 Live Server 之类的静态服务也可以，只要走 http。

## 外观

顶栏第一颗按钮（调色盘）打开，是一间小展柜：每个样式摆在玻璃罩里的台子上，
下面一块名牌，选中的那间罩子亮着、名牌翻成墨底、右上角亮一枚勾。
三排各一个开关：

| 换什么 | 可选 | 说明 |
| --- | --- | --- |
| 色块 | **几何**（默认）/ **自然** / **天空** / **贴纸** / **纯色** | 前四套给每种颜色配一枚图形，压暗一档铺在格子上；纯色就是原来那块平色 |
| 叉 | **叉**（默认）/ **点** | 点是一个小圆点。16×16 满盘时，一片 × 会糊成噪点，点就安静得多 |
| 皇后 | **皇后**（默认）/ **小猫** | 小猫是同一套墨色剪影（没有底色，格子自己的色块色就是它的底），墨色脸上留一对白眼和 ω 嘴 |

- **即时生效**，跟音效 / 冲突高亮一个规矩：选完立刻写 `settings`、存盘、重画，不等「换一局」。
  跟棋盘大小 / 难度 / 挑战那套 `pending` 不是一回事。
- 换的只是**画法**，不碰 `state.marks`：局面、撤销栈、存档里的棋局都不动。
- 自动打的标记和你手标的用同一套样式（自动 / 手动本来就同款，见 `render.js`）。
  设置面板里的「自动打 ×」仍然只管**打不打**，不管长什么样。
- 顶栏那颗按钮上挂一颗小黄点，表示「现在用的不是默认那套」——不然过几天会忘了原来长什么样。
- 落地方式：`<html data-surface / data-mark / data-piece>` 是 CSS 钩子（`17-look.css`），
  格子里的画由 `game/board.js` 的 `pieceSvg()` 决定，色块的图形由 `game/skin.js` 铺上去。
- 老存档没有 `surfaceStyle` 字段、或者存了认不出来的 id（插件被删了），一律按 `styleId()`
  退回各自那类的第一套（也就是几何 / 叉 / 皇后）。

### 色块图案（四套主题）

- **一块底色一枚图形**：图案不是另找颜色画上去，而是把这块自己的颜色乘一个系数压暗
  （`palette.js` 的 `shadeOf`，tone 多在 0.045–0.07）。色相不动，远看还是那一块颜色，
  凑近才认得出是一枚什么图形。这就是「融入」，也是它能和 × 抢不到眼睛的原因。
- **每种颜色一枚**：18 个调色板下标各配一枚图形，同一盘的色块本来颜色就拉得开，
  再加一层各不相同的纹样，色弱的人也认得出是两块。
- **图形只有一层 `<defs>`**：`#skinDefs` 里每种颜色一枚 `<g>`，每格一个 `<use>` 指过去。
  换图案只改 `href` 与一个 CSS 变量，不用把 256 个格子重画一遍。
- 图形是**逐格重复**的：整块色块看过去是一片纹样。图形本身画在 20–80 之间、
  周围留白，所以格子之间有呼吸；16×16（一格二十来像素）时它退成一层几乎看不见的肌理，
  不跟棋子抢。想让图案再安分 / 再明显一点，只改插件里的 `tone`。
- **有的主题整层戴一层纱**（插件里的 `veil`，落成 `--sk-veil`）：
  贴纸那套的白边天生比别的主题亮，满盘铺开时一格格白圈会和 × 抢眼睛，
  所以整层压到 `.45`。这是**这套图案自己的属性**——空着的格子和打了叉的格子
  是同一个模样，没有「平时一套、打叉又一套」。
- 淡化（`.is-dim`）时图案跟着整格一起退掉——淡下去的意思是「这格透了、后面就是纸」，
  留一层图形就成了纸上的水印；冲突格与焦点格会连同图案一起还原。
- **底色只由色块决定，局面不许碰它**：图案的墨色是照这一块**原始底色**算死的
  （压暗或提亮一档，两者是一对），底色一动，这一对就散了。
  所以棋盘上没有「这块放好了 → 整块洗白一档」这种处理
  （以前有过：`.r-ok` + 22% 白。天空那套本来就朝纸白提亮，洗完直接跟底色贴成一片，
  整块图案凭空消失；压暗的那几套也像这块掉色了）。
  「这块有皇后了」色卡上打 ✓，棋盘上就是那只皇后本身。
  想让一块显得「放好了」，只能画在底色之上（描边 / 角标），不能改底色。

四套主题的差别只在**图形**和**往哪个方向偏**：

| 主题 | 18 枚图形 | tone | 偏法 | 观感 |
| --- | --- | --- | --- | --- |
| 几何 | 圆 / 三角 / 菱形 / 十字 / 六边形 / 竖纹 / 圆环 / 星 / 四叶 … | 0.045 | 压暗 | 规整的刻纹，最安静（默认） |
| 自然 | 叶 / 五瓣花 / 蘑菇 / 麦穗 / 蕨 / 松树 / 水滴 / 蝴蝶 / 仙人掌 … | 0.05 | 压暗 | 有机形，盘子看着软一点 |
| 天空 | 云 / 太阳 / 月牙 / 彩虹 / 闪电 / 风筝 / 彗星 / 星座 / 龙卷 … | 0.22 | **提亮** | 浮着一层薄云，最轻 |
| 贴纸 | 心 / 星 / 笑脸 / 花 / 皇冠 / 音符 / 对话框 / 爪印 … | 0.07 | 压暗 + 白边 + 纱 `.45` | 轮廓外一道浅白边，整层很轻，像裁下来贴上去又垫了张薄纸 |
| 纯色 | 无 | — | — | 什么都没有，就是原来那块平色 |

- 天空那套反着来：`ink: 'tint'` 让它走 `tintOf`（朝纸白混），像云从色块里浮出来，
  而不是凹进去。压暗的那几套在同一块浅色上容易糊，提亮反而留得住形状。
- 贴纸的「白边」是把同一份形状先画一遍白（填充与描边都白，描边 8），再压一遍本色。
  白是 **.46 半透明**、整层再戴 `.45` 的纱——0.88 时满盘白圈比别的主题都抢眼，
  0.62 时和 × 挤在一格里仍然吵，走到 .46 × .45 才是「远看有边、凑近才看出是白的」。
  面板里的预览也戴纱（开方到 .67，小盘四十来像素全戴上就糊成一片）。
- `ink` 只有 `'shade'`（默认）/ `'tint'`（天空用），`veil` 默认 1（不戴纱）。
  两类写法都见 `looks/index.js` 开头。

### 插件

外观是插件化的，都在 `src/js/looks/`：

```
looks/
├─ index.js      登记处：把插件摊平成「色块 / 叉 / 皇后」三张表，面板和棋盘都问它
├─ classic.js    墨线：纯色、叉 / 点、皇后 / 小猫（出厂那套）
├─ geometry.js   几何：每种颜色一枚几何图形
├─ nature.js     自然：叶、花、蘑菇、麦穗、蕨、蝴蝶……
├─ sky.js        天空：云、太阳、月牙、彩虹、闪电、风筝……（唯一走提亮的）
└─ sticker.js    贴纸：心、星、笑脸、皇冠、音符、爪印……（带白边）
```

- 一个插件可以只提供一样东西，也可以三样都给；面板按登记顺序长出展位。
- **插件名和样式名不一样时**，展位左上角挂一个小标签写插件名。现在只有「纯色」会挂
  「墨线」——另外四套的主题名就是插件名，再标一遍是重复；叉和皇后两排各自只有一个插件，
  更不标。
- 加一个插件：在 `looks/` 里新建一个文件（导出一个对象），然后在 `looks/index.js`
  的 `PLUGINS` 里加一行 `import`。面板、存档兜底、CSS 都不用动。
- 色块那排是 3 列网格，现在 5 套排成两行。再加就要么排到第 3 行、要么在
  `17-look.css` 里调 `#surfaceRow` 的列数——注意它用的是 id 选择器，
  `18-responsive.css` 里要压它的尺寸也得带 `#surfaceRow` 前缀。
- 插件里能写什么、三类各自的字段，`looks/index.js` 开头有一段完整说明；
  图形一律 `viewBox 0 0 100 100`、只给形状不给颜色（填色继承外面）。

## 填写与拖动

轻点一格打 ×，再点一次取消；同一格 340ms 内点两下就是放皇后（放下的皇后再点一下拿走）。
按住不放拖出去，就是连涂：

| 模式 | 怎么涂 | 开关 |
| --- | --- | --- |
| 按行列对齐（默认） | 起手方向定死这一笔：横向只涂落笔那一行，纵向只涂那一列 | 「拖动按行列对齐」 |
| 随意涂 | 跟着手指走，斜着、绕圈都行（指针出棋盘就停手，不往边上贴） | 同上，关掉 |

- 每一格真的涂上（不是划过去已经标过的），都会**单独震一下**：手指盖住了棋盘，
  靠这一下知道「这格算进去了」。震动跟着设置里的「震动」开关走，关掉就安静。
- 音效仍然是 40ms 一次（`paintTick`）：一整笔几十格，逐格响会糊成一片噪音；
  触觉那边本来就只有一格一下这么细，不需要节流。
- 一笔结束时才写一次盘（`endStroke` → `save()`），拖动途中不碰 localStorage。


## 只差皇后时的一键补齐

推到最后一屏，棋盘上通常只剩皇后位是空的：一只只去找、去双击，纯粹是体力活。
这时候**提示行整行换成一个「只差 N 只皇后 · 补齐」的按钮**，点一下挨个落子，
一串快动画把棋盘收尾。

什么时候才露（`game/rules.js` 的 `pendingQueens()`，三条缺一不可）：

| 条件 | 为什么 |
| --- | --- |
| 已经放下的皇后全在解位上 | 放错位置的话，怎么补都赢不了 |
| 解位上没有被手标 × | 那种格补不进去（也不替玩家擦） |
| 棋盘上「还没标记」的格子数 = 缺的皇后数 | 保证除了皇后位，别处都已经划掉了 |

- **第三条是这件事的边界。** 没有它，一开局就满足（解位当然是空的），
  「补齐」就成了自动求解。反过来只要它成立，剩下的空格就**一定**是那几只皇后：
  每只皇后各占一行一列一块，别的皇后叉不到它的位置，所以解位永远是「活格」。
- 判据只看棋盘上**看得见**的东西（皇后、手标 ×、自动打叉画出来的 ×），
  跟「自动打叉」开不开无关：关掉以后就得自己把别处划干净，按钮才会露。
- 它长在提示行里，不是一块浮层：那是玩家一直在读的那句话的位置，不用去别处找；
  提示行高度还是 36px，**棋盘一格都不会挪**（e2e 里那条「浮层不许挪棋盘」照样成立）。
  正文在这时藏起来——按钮上已经说了「只差几只」，不必再说一遍。
- 点下去：整串**只压一个撤销点**（`pushHistory` 一次），后悔了退一步就回到补齐之前；
  落子间隔按总数摊开、整串压在一秒上下（14 只约 78ms 一只），一只一声音高往上爬的短音；
  期间 `view.filling = true`，棋盘只读，手快也抢不过动画。
- **赢还是 `checkWin()` 判的**（落满 + 无冲突 + 每块一只），跟手动落子走同一条路，
  所以这条捷径没法把一盘没解开的棋判成解开。
- 挑战里勾了「禁用提示」就不露——那一档的意思就是「全自己来」。
- 落地：判据 `game/rules.js` 的 `pendingQueens()` → 露不露 `ui/hint.js` 的 `setNudge()` →
  点击 `app/actions.js` 的 `fillQueens()`；样式在 `04-stage.css`（`.finish-nudge`）。

## 淡化

棋盘填到一半以后，满屏的 × 和皇后会跟还没处理的空格抢眼睛。设置面板「显示更多选项」里
有两个开关，**即时生效**（跟音效 / 冲突高亮一个规矩，不用换一局），**默认都关着**：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 淡化 × | 关 | 手标和自动打的 × 格子整格透成背景色 |
| 淡化皇后 | 关 | 放了皇后的格子整格透成背景色 |

- 默认关掉，是因为淡下去连「这格处理过了」的分量一起没了——满盘 × 淡成一张纸，
  反而看不出自己做到哪。想要安静的棋盘再自己拨开。
- 设置存档带版本号（`SETTINGS_VERSION`，现在是 2）：老存档里「淡化 ×」是旧默认（开），
  读进来一律按新默认（关）走，别的偏好照旧保留。

- 淡的是**整个格子**：底色直接换成背景纸色（`--bg-body`），格子里的画（× / 皇后）
  再退到一档透明度。**不是把颜色掺白**——掺白只会得到一层更浅的彩色，凑近看还是一坨颜色；
  换成纸色才是「这一格透了、后面就是纸」。经纬细线留着，所以它还看得出是一格，
  只是这一格已经没有颜色了。
- **色块边线不淡**：它画在棋盘的另一层（`#rb` 那张 SVG，见 `05-board.css`），
  根本不在这套 `.cell` 里。块与块的界线是解题信息，格子里填过什么是「做过的活」，
  两件事本来就该分开对待，所以格子怎么退，块界都照样清楚。
- 冲突的格子不淡（底色还原成色块色），键盘焦点落在哪一格就把哪一格还原。
- **0.5 秒防抖**：刚落下的子、刚打的叉先原样亮着，手停下来半秒才一起淡下去。
  没有这道延迟的话，连标十几格就是十几下「亮 → 暗」的闪，比不淡还吵。
  等待期间已经淡着的格子不动：新的一笔只点亮刚变的那几格，整盘不会闪一下。
- 判断只看 `state.marks` / `state.auto`（这格有没有 ×、有没有皇后），
  跟外观面板选的是哪种画法无关——以后加新外观不用动 `ui/fade.js`。
- 落地：`settings.fadeMark` / `settings.fadeQueen` + `.cell.is-dim`（`06-board-states.css` 管淡成什么样，
  `DIM_DELAY` 管等多久）。续玩恢复出来的盘直接就淡着，不会先整盘亮半秒。
- 解开那一刻皇后那几格亮回来（`.board.is-won` 里那一条）：这盘棋就是奖品，不该还灰着。

## 难度与尺寸

设置面板上半部分是两个绑在一起的旋钮：**目标难度**决定「开放哪些尺寸 + 分数下限」，
**棋盘大小**在这个范围里挑。都只写 `pending`，点「换一局」才落地。

| 档位 | 开放尺寸 | 分数下限 | 实际拿得到 |
| --- | --- | --- | --- |
| 不限 | 4×4–16×16（常用 6/8/10/12/15） | — | 看尺寸和盘面，1.0–9.9 都可能 |
| 容易 | 4×4–5×5 | — | 只可能是容易（16 格、4 个色块，物理上难不起来） |
| 中等 | 6×6–8×8 | 5.5 | 中等为主，偶尔容易 |
| 困难 | 9×9–13×13 | 7.0 | 困难为主，13×13 常直接是极难 |
| 极难 | 14×14–16×16 | 8.4 | 14×14 约一半、15/16 约八成能抽到 |

- **尺寸不再是难度的另一种写法。** v2 刻度（`engine/difficulty.js` 的 `scale()`）只看
  「这盘要做多少功」：`尺寸基线 + 试推深度 + 开局卡壳`，三项各管一件事——
  边长决定「一次功有多贵」，`probes` 是「假设→矛盾」做了多少次，
  `l3Steps / n` 是开局纯逻辑推进率（0 = 第一只就得假设）。
  色块面积、邻接边数这些跟难度实测相关性 < 0.31，不再进分数。
- 后果是**跨尺寸不再严格单调**：13×13 的中位分可能低于 12×12，因为 13×13 的难度分布
  比 16×16 还宽。这是实测事实，不是 bug——信息页底部的「读数与实际的差异」里写了一条。
- **挑盘**在 `app/puzzle.js` 的 `roll()` / `pickBoard()`：同一个尺寸最多生成 3 张，
  取分数最高的，一旦够到档位下限就提前收手（平均抽 2 张左右，跟改之前差不多）。
- **不够格的盘不装。** 一批 3 张都没够到下限时，棋盘保持原样，弹出
  「没抽到够格的盘」那一层（`ui/mismatch.js`）：写着要多少分、这批抽了几张、最高到多少，
  然后只给两条路——**再抽一局**（同一档同一尺寸再来一批）或**更换设置**
  （打开设置面板并停在这一档上，可以换更大的尺寸或换档）。
  这一层 Esc 关不掉：关掉之后既没新盘也没旧盘，只剩一块空棋盘。
  道理很简单——目标难度是玩家设的，凑合装上一盘「不够格」的等于把他的设置当摆设。
- 档位区间与下限来自实测的可达性矩阵，重跑用 `node tools/scale-matrix.mjs`
  （`--per=48` 加样本）；验收用 `node tools/check-scale.mjs`。
- **老战绩**是按旧刻度打的档（13×13 那时算极难），记录里没有 `sq` 字段。
  它们在列表里留着、挂一个「旧刻度」角标，但**不进排行榜**——新旧分数不可比。
- 落地：`DIFF_BANDS` / `min`（`core/config.js`）→ `roll()` / `pickBoard`（`app/puzzle.js`）→
  `showMismatch()`（`ui/mismatch.js`）+ `syncSheet()` 按档位夹尺寸、重建快捷尺寸按钮（`ui/settings.js`）。

## 挑战

设置面板里「换一局」上面那一组，目前有三项。**跟棋盘大小、目标难度同一个规矩：
只写 `pending`，点「换一局」才落地**——中途改完不换局就等于没改，
开了限时又反悔也不用担心这局被倒计时追着跑（面板标题会变成「挑战 · 待换一局生效」）。

| 选项 | 作用 |
| --- | --- |
| 限时 | 3 / 5 / 10 / 20 分钟挡位，本局第一次操作后开始倒计时；超时判负，结果层第一按钮是「重试这一局」（同一盘棋重开，限时不换） |
| 禁用提示 | 「提示」按钮灰掉，键盘 `H` 也被拦住；只剩皇后时的「补齐」也不露 |
| 禁用撤销 | 「撤销」按钮灰掉，`Z` / `Ctrl+Z` 也撤不动（「清空」不受影响） |

几个刻意的取舍：

- 挑战的落地时机就是 `btnShuffle`：`commitChallenge()` 把 `pending.*` 写进 `settings.*`，
  紧接着 `newGame()` → `applyBoard()` 再把 `settings.timeLimit` 落到 `state.limit`（起算点归零）。
- 剩余时间 = `限时 - (已用 - state.limitFrom)`。正常开局的 `limitFrom` 是 0，
  这个偏移量只是给「同一盘重试 / 特殊情况下补开限时」留的余地。
- **切后台不扣时间**：倒计时跟着 `elapsed` 走，`elapsed` 只在页面前台时增长，跟普通计时一致。
- 超时后 `state.status = 'lost'`：棋盘只读、按钮全灰、结果层不能 Esc 掉，
  必须选「重试这一局」或「换一局新的」。
- 限时与起算点写进对局存档，刷新之后倒计时接着走，不会白捡时间。

## 结果层

解开与超时共用一张卡（`.result`），按钮按结局换：

| 结局 | 主按钮 | 次按钮 |
| --- | --- | --- |
| 解开 | 再来一局（换新盘） | **重来这局**（同一盘从零再下一遍） / 看看棋盘（只收面板） |
| 超时 | 重试这一局（同一盘重开） | 换一局新的 |

「重来这局」走的是 `retryGame()`：不重新出题，`regions` / `solution` / `seed` 原样复用，
用时、标记、撤销栈、提示计数一起归零；同一盘的战绩会再记一条。
超时那屏不给它——主按钮本来就是这件事。

## 战绩与排行榜

顶栏第三颗按钮（奖杯）打开，两个标签页：

**记录** —— 每局结束（解开或超时判负）写一条，新的在最上面。一条里有：

- 棋盘缩略图：按这盘的色块现画的 SVG（配色跟棋盘上完全一致，一眼能认出是哪盘）
- 用时、尺寸、难度档与体感分；小字里是限时、挑战标记、步数与结束时间
- 点开展开：完整分享码 + 复制代码 / 复制链接 / 玩这盘 / 删除

**排行榜** —— 先按限时、再按难度分组，组内只比用时：

| 维度 | 挡位 |
| --- | --- |
| 限时 | 不限 / 3 / 5 / 10 / 20 分钟（就是 `LIMIT_OPTIONS`） |
| 难度 | 容易 / 中等 / 困难 / 极难（本局难度评估的 `tone`） |

不同限时、不同难度的时间本来就没法比（把 3 分钟的中等和 20 分钟的困难放一张表，
第一名永远属于最简单的那个），所以干脆分成 5 × 4 个独立榜单。
打开面板时默认落在**当前这一局**的组合上；胶囊上的小数字是这个组合里的成绩数。
输掉的局记在记录里但**不进榜**。

几条实现上的约定：

- 记录只增不改：一局结束写一条，最多留 300 条（`RECORD_MAX`），超出丢最老的。
- 存的是压缩数据：色块与解各压成十六进制串（`n*n` 与 `n` 个字符），
  8×8 一条约 200 字节。分享码不存，用的时候由 `encodeShare()` 现算。
- 列表一次只画 20 条（`RECORD_PAGE`），剩下的点「显示更多」——
  300 条一起画会把面板卡住。
- 排行榜每组最多显示 12 名（`RECORD_TOP`）。
- 删除 / 清空都要点两次（第一次只是把按钮变红改字），误触不会丢数据。
- 写盘失败（隐私模式、配额满）一律静默：战绩没了也不能让正在玩的局崩掉。

### 分层与依赖方向

```
looks  ←  core  ←  game  ←  ui  ←  app
（画法） （基础设施）（棋局逻辑）（界面）（流程编排）

ui/panels/*  →  core/sheet.js（浮层基座）
ui/panels/index.js 是这些面板唯一的清单
```

- **只能向下依赖**：`looks` 谁也不引用（纯数据与画法），`core` 不引用 `game / ui / app`，
  `game` 只引用 `core / looks`，`ui` 引用 `core / game / looks`。
  `core/config.js` 只向 `looks` 要一个「默认选哪一套」，别反过来让 `looks` 认识设置。
- `events.js` 与 `main.js` 在最上层，可以引用任何模块。
- 有几处刻意保留的互相依赖，别硬拆（拆了反而更绕）：
  `ui/layout ↔ ui/guide`（重排要重画圈画层，引导翻页要重排）、
  `ui/panels/settings ↔ ui/share`（面板里要刷新分享码，载入分享码要关面板）、
  `ui/guide → app/actions`（点「照做」要落子，落子又要收起面板）、
  `ui/share → app/puzzle`（载入分享码其实就是换一盘棋）、
  `ui/panels/result ↔ app/puzzle`（结果层的按钮要开新局，换盘时要先收掉结果层）。
  ESM 允许循环引用，**前提是只在函数体内用对方**——不要在模块顶层求值时读对方的值。

### 加一个浮层面板

浮层（设置 / 本局信息 / 战绩 / 外观 / 结果层 / 「没抽到够格的盘」）都是**一个文件**：
markup、元素引用、事件、开关全在 `src/js/ui/panels/xxx.js` 里。加一个新的只要两步：

1. 照 `ui/panels/look.js` 抄一个文件，导出 `mount(host)`：里面先
   `host.insertAdjacentHTML('beforeend', HTML)`，再取引用、绑事件，最后
   `createSheet({ id, wrap, panel, opener, ... })`；
2. 在 `ui/panels/index.js` 的 `PANELS` 里加一行 import 和一项。

**不用动** `index.html`、`core/dom.js`、`events.js`、`app/actions.js`、`core/state.js`：
- `index.html` 只有一行 `<div id="sheets"></div>` 当挂载点；
- `canPlay()` 只看 `view.sheet`（字符串），浮层基座负责维护它；
- Esc / Tab / `inert` / `aria-expanded` / 互斥都在 `createSheet` 里，面板只声明行为。

`createSheet` 认的字段（写在文件开头也有说明）：`id`、`wrap`（整层，关时 hidden）、
`panel`（焦点与 Tab 容器）、`opener`（触发按钮）、`focusOpener`（关时焦点回不回去）、
`inert`（默认 true，整屏盖住的那两层传 false）、`beforeOpen` / `afterOpen` /
`beforeClose` / `afterClose`、`canClose(opt)`（返回 false 就 Esc / 点背景都关不掉，
只有传 `{ force: true }` 才收）、`onKey(e)`（层内额外快捷键）。

外部要开某个面板，`import` 它导出的 `openXxx()`，或者直接用基座的
`openSheet('xxx')`（不用认识那个模块）。

> markup 是**同步**插进去的模板字符串，不要改成 `fetch('xxx.html')`：那会让启动变成
> async，`tools/` 里所有等 `__QUEENS_DEBUG__` 的断言都得改，首屏还会闪一下空面板。

## 后续打包

现在没有构建工具，浏览器原生跑 ESM。将来要打包时：

1. 以 `index.html` 为入口，Vite / Rollup 能直接吃掉这套原生模块，无需改代码
   （浮层的 markup 已经是 JS 里的模板字符串，不用 `?raw` 再引一次）；
2. `src/js/engine/` 三个文件是「经典脚本 + CJS 双模」，浏览器里挂在 `window.Queens*`、
   Node 里用 `require`（`tools/` 大量依赖）。要转成纯 ESM 时，记得同步改 `tools/` 的 `require`；
3. `index.html` 里的 17 个 `<link>` 会被打包器自动合并，不用手工合并 CSS。

## 约定

- 键盘：`X` 标叉、`Q`/`Enter` 放皇后、`Z` 撤销、`Shift+Z` 重做、`H` 提示、`N` 新局、`Esc` 关浮层。
  挑战里禁用撤销 / 提示时，`Z` 与 `H` 只会换一句「挑战模式：这局不能…」。
- 存档键：`queens.settings.v1` / `queens.game.v1` / `queens.records.v1`（改结构要升版本号）。
- 外观存在 `settings.surfaceStyle` / `markStyle` / `pieceStyle`，页面上表现为 `<html data-surface / data-mark / data-piece>`；
  它只改画法，别往里塞会影响规则的东西（那属于「挑战」）。
- 面板类浮层（设置 / 本局信息 / 战绩 / 外观）打开时 `app` 会被设成 `inert`，`canPlay()` 也要一起拦——
  键盘事件挂在 `document` 上，不拦的话面板背后还能落子。
- 对局存档里的 `limit` / `limitFrom` 是挑战的限时与倒计时起点，老存档没有也照样读。
- 战绩每条都自带一份色块与解（`rg` / `so` 十六进制串），所以删掉最后一局的存档也不会让
  记录里的缩略图和分享码失效；读盘时逐条校验，坏掉的那条丢掉、不连累整份。
- 分享码格式：`QNS1-<边长>-<色块>-<解>-<校验>`，见 `game/share-code.js`。
